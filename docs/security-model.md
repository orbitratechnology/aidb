# Security model

This document states the rules aidb enforces, the controls that implement them today, and the
controls that must exist before each risky feature ships. It is written before any database
writes exist and is updated with every feature that touches a boundary. Threats and their
mitigations are listed in [threat-model.md](./threat-model.md).

## Principles

1. **The Rust core is the only authority.** It holds credentials, opens connections, classifies
   operations, issues and checks approvals, and executes. The UI and the model only request.
2. **The model never executes anything.** It proposes typed plans; deterministic Rust code
   validates them, and writes need a fresh, exact, single-use approval.
3. **Secrets never leave their store.** Database passwords and API keys live in the OS credential
   store or in memory for the session. Never in SQLite, logs, exports, prompts, errors or the UI
   after entry.
4. **Untrusted by default.** Database content, comments, files, model output and provider
   responses are data, never instructions, and never change policy.
5. **Fail closed.** Unknown commands, unclassifiable statements, malformed plans and failed
   approval checks are rejected and audited.
6. **Local only.** No app server, account, telemetry or cloud sync. Network traffic goes only to
   the database and AI provider the user configured.

## Trust boundaries

| Boundary                | Trusted side | Untrusted side                              | Enforced by                                                                                                                                                                     |
| ----------------------- | ------------ | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Webview → core (IPC)    | Rust core    | UI code, npm dependencies, rendered content | Isolation hook, capability ACL, input validation in Rust                                                                                                                        |
| Core → PostgreSQL       | Rust core    | Server responses, row data, error text      | TLS, role grants, bounded reads, redaction (from 4.2)                                                                                                                           |
| Core → AI provider      | Rust core    | Model output, tool calls, provider errors   | TLS, response bounds, redaction (7.1); typed tool registry, computed risk, untrusted framing (8.1); planner loop with limits, consent gate and verification (8.2); policy (9.x) |
| User files → core       | Rust core    | CSV, SQL, JSON, Markdown, text attachments  | Read in the webview only when picked; name, kind, size and text checked again in Rust; framed as untrusted; sent only to local providers or with consent; never executed (8.3)  |
| Webview → outside world | —            | Any URL                                     | CSP, navigation guard, validated `open_external_url`                                                                                                                            |

Database messages shown in the editor pass through redaction; the SQL text is never logged.                                                                                                                                                            | `src-tauri/src/domain/sql.rs`, `src-tauri/src/services/query.rs`, `src-tauri/src/adapters/postgres/query.rs`              |
| SQL editor drafts                  | Tab drafts are kept in webview local storage on this device so they survive restarts (they can hold literals the user typed). SQLx's own statement logging is off, so SQL text never reaches the log.                                                                                                                                                                                                                                                                                                                                                                                           | `apps/desktop/src/features/sql/editor-store.ts`, `src-tauri/src/adapters/postgres/options.rs`                             |
| AI provider transport              | Only the core calls providers (the webview has no network access). Streams are bounded (1 MB per event, 4 MB and 64 tool calls per response); malformed tool arguments are kept apart and never run, and turns that were refused or cut short have no runnable calls. Requests can be cancelled and have a time limit. |
| AI provider profiles               | Profiles are validated in Rust (lengths, `http(s)` endpoints without credentials, query or fragment). Plain HTTP to another machine needs an explicit acknowledgement, re-checked every time a client is built from a stored profile. API keys go only to the OS credential store (or session memory), are checked to be header-safe, never appear in profile details, logs or errors, and are deleted with their profile. "Test provider" sends only fixed prompts and never database content.                                                                                                                                                                                               |
| AI assistant switch and disclosure | AI is off until the user turns it on; the core accepts only an existing provider and turns AI off when that provider is deleted. Settings › AI providers always shows what the assistant sends (the question and conversation, the open connection's schema structure, and rows or attached files only with consent in that conversation) and what it never sends (credentials, other connections); choosing a hosted provider shows it again with the destination host and asks for confirmation. The agent (phase 8) is bound by this list.                                                                                                                                                 |
| Assistant tools and context        | The model can call only the registry's read tools (R0/R1); every call is parsed into a typed input that rejects unknown tools, unknown or malformed arguments and anything but a single read statement, before anything runs. Risk and required approval come from the registry and are recomputed whenever a plan is read or loaded. Database text, attached files and tool results are framed in a per-request random tag the content cannot close, under an explicit rule that they are data, never instructions; context is budgeted with visible truncation and listed for review, flagging items with data values.                                                                      |
| Assistant tasks                    | Every model call is checked by the registry, added to the plan within R1, held back when it would send data values without consent, and run through the editor's read path (read-only transaction, timeouts, 50 rows). Limits on rounds, steps, refused calls and time; one question at a time; Stop cancels the model request and the running statement. Fixed checks decide whether an answer counts as checked.                                                                                                                                                                                                                                                                            |
| Ask screen                         | Context is reviewed before sending; files are read only when picked, checked again in Rust, and sent to a hosted provider only with this conversation's consent. Answers render as text, never Markdown or HTML; SQL in them only opens in an editor tab.                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Assistant evaluation               | Scripted cases replay injected comments, rows, files and fake frame tags, writes in read tools and malformed calls against the real tools on PostgreSQL 15 to 18 in CI, checking that the database is unchanged, no password reaches the model, untrusted content stays framed and nothing above R1 runs. A benchmark measures answers and injection resistance for a given model.                                                                                                                                                                                                                                                                                                            |
| Query history and saved queries    | History is written only by the core, after a first-page run: the text is redacted (secret patterns and role `PASSWORD '...'` literals) and cut at 100,000 characters before it is stored, and only the newest 1,000 entries are kept. Entries are deleted with their connection and can be removed one by one or cleared in Settings › Storage. Saved queries hold only what the user saves (name up to 200 characters, SQL up to 1 MB), validated in Rust, and never run on their own; opening one only fills an editor tab.                                                                                                                                                                 |

Accepted risk: while a session is open, the PostgreSQL driver keeps the password in memory to
open pool connections; its options are never printed or logged (their `Debug` output would
include it). Read-only sessions rely on `default_transaction_read_only`; SQL from the editor
cannot turn it off: `SET` and `set_config()` are refused, and every run uses its own `READ ONLY`
transaction that is rolled back. Database role grants remain the final boundary.

Accepted risk: user-defined functions called from a read are not inspected. The read-only
transaction stops them from writing, but a `SECURITY DEFINER` function could still act outside
the transaction (for example, `dblink` inside it). Connect with least-privilege roles.

Accepted risk: a CSV export opened in a spreadsheet can evaluate cells that start with `=`, `+`,
`-` or `@` as formulas. aidb writes values exactly as the database stores them, as other database
clients do; the user decides where the file is opened.

Accepted risk: `style-src` allows inline styles (Radix overlays and Sonner inject `<style>`
elements). This permits CSS injection, not script execution. See [decisions.md](./decisions.md).

## Gates before features ship

Each gate must be implemented and tested before the feature that depends on it is enabled.

| Gate                                                                                                                                                                                                                  | Required before                   | Task                             |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- | -------------------------------- |
| OS credential store with session-only fallback; no plaintext fallback; tests prove secrets never reach SQLite, logs or exports                                                                                        | Saving any connection or API key  | Done (3.2); export test with 4.1 |
| TLS on by default with certificate verification; disabling TLS for a remote host needs an explicit, recorded override                                                                                                 | First PostgreSQL connection       | 4.1, 4.2                         |
| New connections read-only by default; statement timeouts and row/byte caps on every read                                                                                                                              | Running queries                   | 4.2, 6.1                         |
| Statement classification with `sqlparser` plus database-side checks; unknown or multi-statement agent SQL rejected                                                                                                    | Manual SQL execution, agent reads | 6.1, 8.1, 8.2                    |
| AI endpoints: HTTPS required except loopback; explicit acknowledgement for insecure remote endpoints; disclosure of what is sent                                                                                      | Any provider request              | Done (7.2, 7.3)                  |
| Context minimization: schema-first, row data and files only with explicit consent; budgets with visible truncation                                                                                                    | Agent with hosted providers       | Done (8.1–8.3)                   |
| Deterministic R0–R4 risk classifier; approval state machine; approvals bound to connection, environment, statement, parameters, schema fingerprint and policy version; short-lived and single-use; redacted audit log | **Any write, agent or manual**    | 9.1–9.3                          |
| R4 (destructive/privileged) blocked in agent tools                                                                                                                                                                    | Agent writes                      | 9.1, 10.3                        |
| Transactions with rollback on failure; uncertain commit outcomes reported, never retried automatically                                                                                                                | Data changes, imports, migrations | 10.1–11.2                        |

## Rules for contributors

**Adding a command:** validate every argument in Rust, return `AppResult`, instrument with
`skip_all`, list it in `build.rs`, grant it in a capability, add its name to `COMMANDS` in the
contracts package, and add an ACL test if it is sensitive.

**Adding a plugin:** only official or well-maintained plugins; review its permissions; grant the
minimum; prefer calling it from Rust after validation rather than granting webview access. Plugin
commands reachable from the webview must also be allowed in the isolation hook.

**Handling secrets:** never format a secret into a message, log line, error or event. Wrap secret
values in a type whose `Debug` and `Display` print `[redacted]`.

**Rendering untrusted content:** render data as text. Never use `dangerouslySetInnerHTML` for
database values, model output or file contents. Assistant answers are plain text with fenced
code shown in code blocks; Markdown is not rendered, links are not made clickable, and nothing in
an answer runs (SQL opens in an editor tab only when the user asks).
