# Threat model

Scope: the aidb desktop app (Rust core, webview UI, isolation hook), its local data, and its
connections to a user's PostgreSQL database and optional AI provider. Controls are described in
[security-model.md](./security-model.md). Review this document whenever a feature adds a new
input, output, permission or dependency.

Status legend: **Done** (implemented and tested) · **Planned** (task number) · **Accepted**
(residual risk, with reason).

## Assets

| Asset                                     | Why it matters                                          |
| ----------------------------------------- | ------------------------------------------------------- |
| Database credentials                      | Full access to the user's data within the role's grants |
| AI provider API keys                      | Billing and account abuse                               |
| Database contents                         | Confidential data; integrity of production systems      |
| Local metadata (profiles, history, audit) | Reveals infrastructure and past queries                 |
| The user's machine                        | The app must not become a path to code execution        |

## Threat sources

- Hostile **model output**: hallucinated or destructive SQL, invented tools, false risk labels.
- **Prompt injection** in database rows, comments, column names, attachments or provider replies.
- A **compromised npm or crate dependency** running code in the webview or core.
- **Hostile content rendered in the UI** (database values, file contents) attempting script
  injection.
- A **malicious or compromised endpoint**: database server or AI provider returning crafted data.
- **User error**: acting on the wrong connection, especially production.
- **Network attackers** between the app and its database or provider.

## Threats and mitigations

| #   | Threat                                                                                                                | Mitigation                                                                                                                                                                                                                                                                                                          | Status                                                                               |
| --- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| T1  | Injected script in the webview calls native commands                                                                  | CSP blocks inline and remote scripts; React escapes rendered text; isolation hook and capability ACL limit reachable commands                                                                                                                                                                                       | Done                                                                                 |
| T2  | Compromised frontend dependency calls plugin APIs or unlisted commands                                                | Isolation hook allows only app commands, event plugin and channel transport; ACL grants only listed commands; unencrypted IPC rejected                                                                                                                                                                              | Done                                                                                 |
| T3  | Webview navigated to an attacker page that then uses IPC                                                              | Navigation guard blocks non-app URLs; capabilities apply only to the local app origin                                                                                                                                                                                                                               | Done                                                                                 |
| T4  | Webview used to exfiltrate data over the network                                                                      | CSP `connect-src` allows IPC only; images and fonts only from the bundle                                                                                                                                                                                                                                            | Done                                                                                 |
| T5  | Malicious link opens a dangerous scheme or credential-bearing URL                                                     | `open_external_url` allows only `https`, loopback `http`, `mailto`, and rejects embedded credentials                                                                                                                                                                                                                | Done                                                                                 |
| T6  | Secrets leak through errors or logs                                                                                   | Error contract never serializes causes; redaction on messages, causes and panics; commands skip arguments in logs                                                                                                                                                                                                   | Done                                                                                 |
| T7  | Secrets persisted in plaintext                                                                                        | OS credential store or session memory only; `SecretString` everywhere; `secret_ref` stored only for durable secrets; tests scan database files and captured logs for the secret; keyring errors carrying secret bytes are zeroed and dropped; exports hold no passwords or references (tested)                      | Done                                                                                 |
| T8  | Connection to a spoofed database server                                                                               | TLS with certificate verification (`verify-full`) by default; TLS off for a remote host needs consent on every save; `sslmode=prefer`/`allow` from a URI become `require`, never a plaintext fallback; certificate and host-name checks with the OS trust store                                                     | Done (verified against PostgreSQL 15–18)                                             |
| T9  | Model produces destructive SQL                                                                                        | Model never executes; deterministic classification; writes need exact approval; R4 blocked for the agent; database role grants as final boundary                                                                                                                                                                    | Planned (6.1, 9.1–9.3, 10.3)                                                         |
| T10 | Model claims a low risk or swaps the target after approval                                                            | Risk computed in Rust, not taken from the model; approval bound to connection, environment, statement, parameters, schema fingerprint; single-use                                                                                                                                                                   | Planned (9.1, 9.2)                                                                   |
| T11 | Prompt injection in rows, comments or attachments changes behavior                                                    | Content framed as data; cannot add tools, change policy or approve; tool calls validated against a fixed registry; the evaluation suite replays injected comments, rows, file contents and fake frame tags against the real tools                                                                                   | Done (8.1, 8.2, 8.4)                                                                 |
| T12 | Sensitive data sent to a hosted model without consent                                                                 | Schema-first context; row values and files only with explicit opt-in; visible context list before sending                                                                                                                                                                                                           | Done (8.1–8.3)                                                                       |
| T13 | AI endpoint over plain HTTP intercepted                                                                               | HTTPS required except loopback; explicit acknowledgement otherwise                                                                                                                                                                                                                                                  | Planned (7.2)                                                                        |
| T14 | Accidental write to production                                                                                        | Environment shown as text and icon in the top bar and lists; access mode as the server enforces it ("Writes enabled" shown at every width); read-only default; a production warning when writes are turned on; one connection open at a time; approval shows the target; switching connection invalidates approvals | Partly done (1.3, 4.3); Planned (9.2)                                                |
| T15 | Unbounded result or file exhausts memory or freezes the UI                                                            | Row/byte caps, pagination, virtualized grid, file size limits, cancellation                                                                                                                                                                                                                                         | Partly done: server-side statement and lock timeouts (4.2); Planned (5.3, 6.1, 10.4) |
| T16 | Partial failure leaves the database in an unknown state                                                               | Transactions; uncertain commits reported, never retried automatically; verification step after writes                                                                                                                                                                                                               | Planned (10.1, 11.2)                                                                 |
| T17 | SQL injection through identifiers or filter values from the UI                                                        | Identifiers validated against live metadata and quoted; values always bound as parameters                                                                                                                                                                                                                           | Planned (5.3)                                                                        |
| T18 | Supply-chain compromise of a Rust crate                                                                               | Locked versions, reviewed additions, minimal plugins, dependency auditing in CI                                                                                                                                                                                                                                     | Partly done; audit in 12.2                                                           |
| T19 | CSS injection via inline styles                                                                                       | Cannot execute script under the CSP; inline styles are required by Radix and Sonner                                                                                                                                                                                                                                 | Accepted                                                                             |
| T20 | Code in the webview wipes local history or weakens the safety limits                                                  | Clearing limited to three named targets, never connections or saved queries; each clear recorded in the file log outside the webview's reach; limits range-checked in Rust, so they can be loosened only within the allowed ranges; read-only default and approvals do not depend on these settings                 | Done                                                                                 |
| T21 | Hostile import file (oversized, malformed, writable production profiles, smuggled passwords)                          | 1 MB and 1,000-entry caps; per-entry parsing with errors that never echo values; unknown fields such as `password` ignored; every entry validated in Rust and imported read-only; preview before anything is saved                                                                                                  | Done                                                                                 |
| T22 | Password in a pasted connection URI leaks to logs or storage                                                          | URI sent as `SecretString`; command arguments never logged; parse errors never repeat the input; the password returns to the form once and is saved only through the credential store                                                                                                                               | Done                                                                                 |
| T23 | libpq environment variables silently change a connection (`PGPASSWORD`, `.pgpass`, `PGOPTIONS` turning read-only off) | Password file never read; empty password sent when none is saved; aidb's session settings appended after `PGOPTIONS` so they win; both behaviors tested against a real server                                                                                                                                       | Done                                                                                 |
| T24 | A cancel request stops a different statement than intended                                                            | Backend PID recorded per operation; the cancelled connection is closed instead of returned to the pool                                                                                                                                                                                                              | Done                                                                                 |
| T25 | A runaway or blocked statement holds locks or the UI indefinitely                                                     | Server-enforced statement, lock and idle-in-transaction timeouts on every connection; connect timeout on every connection attempt                                                                                                                                                                                   | Done                                                                                 |
| T26 | Decisions made on a stale view of the schema after DDL                                                                | Structural fingerprint checked before a cached catalog older than 15 s is served; any DDL reloads it and drops cached object details; an object found missing forces the check on the next read; reconnecting starts empty                                                                                          | Done (approval binding in 9.1)                                                       |
| T27 | Huge catalogs exhaust memory or freeze the UI                                                                         | Overview capped at 20,000 objects with a visible `truncated` flag; columns and relationships load per object; view queries capped at 100 KB; the tree renders 200 objects per schema at a time                                                                                                                      | Done                                                                                 |
| T28 | SQL injection through table, column or sort names, or filter values, in a page request                                | Names are compared with the live column list and only server-quoted names reach the SQL; values, limit and offset are bound parameters; unknown fields in requests are rejected                                                                                                                                     | Done                                                                                 |
| T29 | Browsing a view or table runs a function that writes                                                                  | Every page read runs in a `READ ONLY` transaction, whatever the connection allows                                                                                                                                                                                                                                   | Done                                                                                 |
| T30 | Huge tables, wide rows or giant values exhaust memory or freeze the UI                                                | Row cap from Safety settings, byte budget with streaming, 2,000-character cells cut on the server, truncation flagged in the page; the grid renders only visible rows                                                                                                                                               | Done                                                                                 |
| T31 | An abandoned read keeps running on the server after the user moves on                                                 | Reads carry an operation id; `cancel_operation` stops them with `pg_cancel_backend`, and the statement timeout bounds the rest; the grid cancels reads it no longer shows                                                                                                                                           | Done                                                                                 |
| T32 | Code in the webview writes or overwrites arbitrary files through the export                                           | The core picks the path in a native dialog; the webview cannot pass a path and receives only the file name; the dialog plugin's commands are not granted                                                                                                                                                            | Done                                                                                 |
| T33 | A huge export exhausts memory or disk unnoticed                                                                       | Rows stream from the database to a buffered file one at a time; at most 1,000,000 rows, with the cap reported; cancellable; partial files removed on failure                                                                                                                                                        | Done                                                                                 |
| T34 | Exported CSV evaluated as formulas when opened in a spreadsheet                                                       | Accepted: values are exported exactly; documented in the security model                                                                                                                                                                                                                                             | Accepted                                                                             |
| T35 | Row data copied to the clipboard without the user asking                                                              | The clipboard is written only from an explicit copy button or Ctrl/Cmd+C on a focused row                                                                                                                                                                                                                           | Done                                                                                 |
| T36 | A write hidden in editor SQL runs (data-changing CTE, SELECT INTO, write in a function)                               | Classifier refuses data-changing statements and constructs; every run is a `READ ONLY` transaction, so the server rejects writes it missed                                                                                                                                                                          | Done                                                                                 |
| T37 | A second statement, or a COMMIT that ends the read-only transaction, is smuggled past the classifier                  | Exactly one statement per run, and the extended protocol makes the server refuse more than one command                                                                                                                                                                                                              | Done                                                                                 |
| T38 | Editor SQL changes session settings (timeouts, read-only default) that persist on a pooled connection                 | `SET`/`RESET`/`set_config` refused; each run's transaction is rolled back, which reverts session settings                                                                                                                                                                                                           | Done                                                                                 |
| T39 | A read calls functions with outside effects (terminate backends, advisory locks, server files, `dblink`)              | Known functions refused by name; role privileges and the read-only transaction for the rest; user-defined functions are an accepted residual risk                                                                                                                                                                   | Done (partial by design)                                                             |
| T40 | SQL text with sensitive literals ends up in logs                                                                      | The SQL text is never logged; only counts, timings and SQLSTATEs; SQLx statement logging (which would log slow statements in full) is off                                                                                                                                                                           | Done                                                                                 |
| T41 | SQL drafts (possibly with sensitive literals) persist on disk                                                         | Kept only in the app's webview storage on this device, never sent anywhere; counted and cleared from Settings › Storage; results are not persisted                                                                                                                                                                  | Done                                                                                 |
| T42 | Query history keeps passwords or keys that appeared in editor SQL                                                     | The core redacts secret patterns and role `PASSWORD '...'` literals before writing; entries are capped in size and number, local only, deleted with their connection, and clearable                                                                                                                                 |
| T43 | Code in the webview forges or alters history, or runs a saved query unseen                                            | No command writes history from the webview; saved queries are validated in Rust, and opening one only fills an editor tab, which runs through the same classifier and read-only transaction                                                                                                                         |
| T44 | A malicious or broken AI endpoint floods the app or sends malformed streams                                           | Every event, response, tool-call count and error body is size-capped; unreadable events end the request with an error; idle and total time limits; manual database features never depend on a provider                                                                                                              |
| T45 | The provider API key leaks through logs, errors, redirects or debug output                                            | Key only in a sensitive header; never in URLs; redirects refused; `Debug` hides it; error text redacted and scrubbed of the key; tests check echoed keys never reach messages                                                                                                                                       |
| T46 | Prompts for a local model leave the machine through a configured proxy                                                | Requests to loopback endpoints bypass all proxies                                                                                                                                                                                                                                                                   |
| T47 | A truncated, refused or malformed tool call is acted on                                                               | Unparseable arguments are kept as malformed and never run; refused or token-limited turns expose no runnable calls; the agent validates calls against its registry (8.2)                                                                                                                                            |
| T48 | Prompts and the API key cross the network unencrypted to a remote endpoint                                            | HTTPS required except loopback; plain HTTP to another machine only with a recorded acknowledgement, re-checked on every use                                                                                                                                                                                         |
| T49 | A tampered local database points a profile at an attacker's endpoint over plain HTTP                                  | Stored profiles are validated again before any request; the trust rule cannot be bypassed by editing a row                                                                                                                                                                                                          |
| T50 | Testing a provider sends user or database data to it                                                                  | "Test provider" sends only fixed prompts, and its dialog says so before any request                                                                                                                                                                                                                                 |
| T51 | A user turns on a hosted provider without understanding what it receives                                              | AI is off by default; the disclosure is always visible, and choosing a hosted provider repeats it with the destination host and needs confirmation (Cancel has focus)                                                                                                                                               |
| T52 | The assistant setting points at a deleted or tampered provider                                                        | The core accepts only existing providers, turns AI off when the chosen one is deleted, and loads a missing one as AI off                                                                                                                                                                                            |
| T53 | Prompt injection in table comments, rows or attached files makes the model act on it                                  | Untrusted content framed in a per-request random tag it cannot close, with a system rule that it is data only; the model's only actions are registry tools, which are R0/R1 and checked in Rust; injection cases join the evaluation suite (8.4); scripted and benchmark injection cases check it (8.4)             | Done (8.1, 8.4)                                                                      |
| T54 | The model calls a tool that does not exist, smuggles extra arguments or a write into a read tool                      | Unknown tools and fields are rejected; SQL must classify as exactly one read; the read-only transaction is the backstop; there is no generic SQL tool                                                                                                                                                               | Done (8.1, 8.2)                                                                      |
| T55 | The model labels a risky plan as safe, or a stored plan is edited to lower its risk                                   | Risk comes from the registry and checked arguments, never the model; the plan's risk and approval are recomputed on every read and load                                                                                                                                                                             | Done (8.1)                                                                           |
| T56 | Large catalogs or files flood the provider or silently lose context                                                   | Budgets per section with visible truncation notices, a reviewed list of context items, and capped tool results                                                                                                                                                                                                      | Done (8.1, 8.3)                                                                      |
| T57 | A model loops, floods tool calls or keeps the database busy                                                           | At most 10 model calls, 25 steps and 5 refused calls per task; 10 minutes per model call; 50 rows per result; the session's statement and lock timeouts apply to every query                                                                                                                                        | Done (8.2)                                                                           |
| T58 | Query results reach a hosted provider without consent                                                                 | Tools that return data values are not run unless the provider is on this computer or the user allowed it; the step is marked skipped and the model is told why; structure tools still run                                                                                                                           | Done (8.2, 8.3)                                                                      |
| T59 | A fabricated or unchecked answer is presented as fact                                                                 | Deterministic checks after every task: an answer exists, the last query it relied on ran, no result it saw was cut, SQL it shows was actually run; otherwise the task is partial or failed, never succeeded                                                                                                         | Done (8.2)                                                                           |
| T60 | Cancelling leaves the model request or a query running                                                                | Cancel drops the model request and cancels the running statement on the server by its operation id; the step and task are recorded as cancelled                                                                                                                                                                     | Done (8.2)                                                                           |
| T61 | Saved tasks keep data the assistant read                                                                              | Tasks (question, steps with their arguments and outcomes, answer) stay in the local database only; full tool results are not stored; Settings › Storage clears them (agent task history); tasks cut off by a quit are closed at the next start                                                                      | Done (8.2)                                                                           |
| T62 | A hostile attached file (binary, huge, a path or control characters in its name, instructions in its text)            | Only .sql, .csv, .json, .md and .txt; at most 5 files of 512 KB, text only (no NUL); the name keeps no path or control characters; content is cut to the budget and framed as untrusted; files go to a hosted provider only with this conversation's consent                                                        | Done (8.3)                                                                           |
| T63 | Model output injects markup or links, or gets SQL run unseen                                                          | Answers are plain text; fenced code is shown in code blocks; no Markdown, HTML or clickable links; "Open in SQL editor" only opens a tab, and the editor runs nothing until the user does                                                                                                                           | Done (8.3)                                                                           |
| T64 | Code in the webview forges conversation history or turns on data sharing                                              | History is capped by the core (six exchanges, answer limit) and only shapes the prompt; sharing applies to one request and each task logs whether data values were allowed; read-only tools and the session's read-only mode still bound what can be read                                                           | Done (8.3)                                                                           |
| T65 | Several questions at once overload the database or the provider                                                       | One question at a time; a second is refused until the first ends or is stopped                                                                                                                                                                                                                                      | Done (8.3)                                                                           |
| T66 | Progress events are lost, reordered or malformed on the way to the UI                                                 | Events go over a Tauri channel (ordered) and are validated with Zod; the outcome is returned on its own and the task is saved by the core whatever the UI receives                                                                                                                                                  | Done (8.3)                                                                           |

## Out of scope

- An attacker who already controls the user's OS account: local data is protected by the operating
  system, and aidb does not add its own encryption layer (PRD: no bespoke cryptography).
- Over-privileged database roles: aidb cannot add safety the database role does not enforce. Users
  are told to connect with least-privilege roles.
- Provider-side data handling once a user chooses to send context to a hosted model.
