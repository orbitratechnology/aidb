# Decision log

Technical decisions for aidb, with the reason for each. Add an entry whenever a dependency,
pattern or default is chosen or changed.

## How decisions are made

1. **Reliability and maturity first.** Use stable releases only. No alpha, beta, release-candidate
   or nightly packages for shipped functionality.
2. **Official recommendations next.** Prefer what a tool's maintainers recommend: official
   templates, plugins, CLIs and documented patterns over community alternatives.
3. **Smallest sufficient surface.** Add a dependency, plugin or permission only when a feature
   needs it, and remove unused ones.
4. **Pin and record.** Lock versions (`Cargo.lock`, `pnpm-lock.yaml`, `rust-toolchain.toml`) and
   write the decision here.

When these conflict, safety and reliability win, and the trade-off is written down.

## Native core

| Decision                                                                                        | Why                                                                                                                                                                                                                                                                                                                                                                                                                                | Alternatives                                                                                                                                   |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Tauri isolation pattern                                                                         | Tauri recommends it whenever feasible, especially for apps with many frontend dependencies. Every IPC message passes a sandboxed hook and is encrypted per launch, which limits what a compromised npm package can reach.                                                                                                                                                                                                          | Brownfield (default) pattern.                                                                                                                  |
| App command ACL via `tauri-build` `AppManifest`                                                 | Official mechanism: each command gets an `allow-*` permission that a capability must grant.                                                                                                                                                                                                                                                                                                                                        | Unchecked app commands (Tauri's default).                                                                                                      |
| Navigation guard plugin (`on_navigation`)                                                       | Official hook; the webview never leaves bundled content.                                                                                                                                                                                                                                                                                                                                                                           | Relying on CSP alone.                                                                                                                          |
| `tauri-plugin-opener` 2.x, used only from Rust                                                  | Official plugin for opening URLs. Its webview commands are not granted and its injected link script is disabled; Rust validates URLs first.                                                                                                                                                                                                                                                                                        | `open` crate directly.                                                                                                                         |
| `tauri-plugin-dialog` 2.x (stable line), used only from Rust                                    | Official plugin for native open/save dialogs. The core shows the dialog and reads or writes the chosen file, so the webview never gets a path or file access; its commands are not granted. The 3.0 line is still alpha.                                                                                                                                                                                                           | `<input type="file">` plus webview downloads (behave differently per platform and put file contents in the webview); `tauri-plugin-fs` scopes. |
| Connection URIs parsed in Rust with `url` and `percent-encoding`                                | One parser for the PostgreSQL URI rules, tested in Rust; the URI arrives as a `SecretString` and errors never echo it. `sslmode=prefer`/`allow` become `require`, since aidb never falls back to plaintext.                                                                                                                                                                                                                        | Parsing in the UI.                                                                                                                             |
| Versioned JSON for connection export (`aidb.connections`, version 1)                            | PRD format choice. Holds settings only (no id, secret reference or password); unknown fields are ignored on import, so a hand-added password is dropped. Newer versions are refused.                                                                                                                                                                                                                                               | JSON Schema file (deferred until another tool needs it).                                                                                       |
| Imports always arrive read-only                                                                 | Keeps the read-only-by-default rule for profiles from another machine or person; the preview says when the file had writes on.                                                                                                                                                                                                                                                                                                     | Trusting the file's `readOnly`.                                                                                                                |
| Consent on every save for TLS-off remote hosts                                                  | PRD: disabling TLS for a remote host needs an explicit override. Not stored, so it is asked again whenever such a profile is saved or imported.                                                                                                                                                                                                                                                                                    | A stored per-profile flag.                                                                                                                     |
| One open connection at a time, enforced in the core                                             | The workspace, its plans and approvals belong to one connection; connecting elsewhere closes the previous session so nothing carries over silently (PRD: no silent connection switch).                                                                                                                                                                                                                                             | Several open sessions with a UI selector.                                                                                                      |
| Connection form limits generated from Rust                                                      | Like the Safety limits: a test writes `ConnectionLimits.ts`, so the form's Zod rules use the core's numbers and CI catches drift.                                                                                                                                                                                                                                                                                                  | Hard-coded limits in the form.                                                                                                                 |
| Ask for a password at connect time; save it only after it works                                 | A mistyped password never lands in the keychain, and saving stays the user's choice.                                                                                                                                                                                                                                                                                                                                               | Save before connecting.                                                                                                                        |
| Catalog from `pg_catalog`, not `information_schema`                                             | `information_schema` hides objects the role cannot use and lacks row estimates, identity and index details; `pg_catalog` is the stable, documented source PostgreSQL's own tools use.                                                                                                                                                                                                                                              | `information_schema` views.                                                                                                                    |
| Structural fingerprint without row versions                                                     | Catalog row versions (`xmin`) change on `ANALYZE`, which would invalidate caches and, later, approvals when nothing structural changed. Digesting definitions (`pg_get_constraintdef`, `pg_get_viewdef`, `format_type` inputs) changes only with DDL.                                                                                                                                                                              | `xmin`-based digest; event triggers (need superuser).                                                                                          |
| Two-level catalog loading, cached in memory                                                     | The tree needs names and kinds only; columns and relationships load per object. Details are never written to disk (PRD), only freshness metadata.                                                                                                                                                                                                                                                                                  | Loading every column up front; SQLite copy of the catalog.                                                                                     |
| Catalog tests in scratch databases                                                              | The fingerprint covers a whole database; a database per test keeps parallel tests from changing it.                                                                                                                                                                                                                                                                                                                                | Serial tests.                                                                                                                                  |
| SQLx 0.9 Postgres with `tls-rustls-ring-native-roots`                                           | SQLx is already the local store's driver; the PRD names it. rustls is pure Rust (no OpenSSL to ship); native roots trust the OS certificate store, so corporate CAs work; `ring` builds everywhere without extra tools.                                                                                                                                                                                                            | `tls-native-tls` (OpenSSL on Linux); `tls-rustls-aws-lc-rs` (needs CMake/NASM on Windows); `tokio-postgres`.                                   |
| Session limits as server settings at connection start                                           | `statement_timeout`, `lock_timeout`, `idle_in_transaction_session_timeout` and `default_transaction_read_only` are sent as startup options, so PostgreSQL enforces them on every pooled connection; they are appended last and override `PGOPTIONS`.                                                                                                                                                                               | Client-side timers only (cannot stop server work).                                                                                             |
| No `~/.pgpass`; empty password when none is saved                                               | Credentials come only from the OS credential store or the user, never silently from `PGPASSWORD` or a password file. Other libpq variables (such as `PGSSLROOTCERT`) behave as in psql.                                                                                                                                                                                                                                            | SQLx's default environment-driven options.                                                                                                     |
| Cancellation with `pg_cancel_backend` from a separate connection                                | SQLx has no public cancel-request API. The backend PID is recorded per operation; a connection that was sent a cancel is closed, never reused, so a late signal cannot hit another statement.                                                                                                                                                                                                                                      | Dropping the future (does not stop server work).                                                                                               |
| First connection opened directly, then a lazy pool (4 connections)                              | A direct connect reports the real failure (refused, TLS, password) instead of the pool's generic timeout; the pool then serves operations.                                                                                                                                                                                                                                                                                         | Eager pool connect.                                                                                                                            |
| Integration fixture: Docker in CI, local binaries otherwise                                     | `scripts/postgres-fixture.sh` starts a TLS-enabled server with a throwaway CA. CI runs the official images for PostgreSQL 15, 16, 17 and 18 (latest minor; the job log prints the exact version).                                                                                                                                                                                                                                  | Testcontainers (adds a Docker requirement locally).                                                                                            |
| `ts-rs` 12 for TypeScript contracts                                                             | Stable release that generates types from Rust DTOs. `tauri-specta`/`specta` would also type commands but are still release candidates.                                                                                                                                                                                                                                                                                             | `tauri-specta` (RC).                                                                                                                           |
| `thiserror` for typed errors, one `AppError` at the IPC boundary                                | Standard in the Rust ecosystem; stable error codes and redacted messages are the UI contract.                                                                                                                                                                                                                                                                                                                                      | `anyhow` everywhere.                                                                                                                           |
| `tracing` with a rotating file appender                                                         | The Rust ecosystem standard (Tokio project). Logging stays inside the core; the webview cannot write to logs, which keeps untrusted content out.                                                                                                                                                                                                                                                                                   | `tauri-plugin-log` (also lets the webview log).                                                                                                |
| Regex-based redaction                                                                           | Defense in depth for untrusted driver/provider text; `regex` is the standard crate.                                                                                                                                                                                                                                                                                                                                                | No redaction.                                                                                                                                  |
| SQLx 0.9 SQLite from Rust, not `tauri-plugin-sql`                                               | PRD: native modules when a plugin would expose SQL to the webview. The official SQL plugin is built for JS-side queries.                                                                                                                                                                                                                                                                                                           | `tauri-plugin-sql`.                                                                                                                            |
| `sqlite-bundled` feature only                                                                   | Ships a known SQLite version on every OS; omits SQLx's extension-loading feature, which the app never needs.                                                                                                                                                                                                                                                                                                                       | `sqlite` umbrella feature (adds extension loading).                                                                                            |
| Runtime-checked literal queries plus tests                                                      | SQLx 0.9 rejects non-literal SQL by default; every query is covered by tests against a real database. Compile-time macros would need a prepared offline cache for little gain on a small schema.                                                                                                                                                                                                                                   | `query!` macros with `cargo sqlx prepare`.                                                                                                     |
| Table pages built from server-quoted names (`quote_ident`) and bound values                     | The column list comes from the live catalog with PostgreSQL's own quoting, so request strings are only compared, never formatted into SQL; values are parameters cast on the server. This is the one statement passed with `AssertSqlSafe` in production code, documented and unit-tested.                                                                                                                                         | Quoting identifiers in Rust; `sqlx::QueryBuilder`.                                                                                             |
| Offset pages ordered by the primary key                                                         | Works for every table and view and for any sort; the primary key as a tiebreaker makes pages stable. Pages say when no stable order exists. Keyset paging needs a unique sort key and cannot jump to a page.                                                                                                                                                                                                                       | Keyset (cursor) paging; server-side cursors held open between pages.                                                                           |
| Values sent as server-rendered text with a kind per column                                      | Lossless for every type, including extensions, enums and domains (exact numerics, ISO timestamps); no per-type decoding to maintain. Arrays use `to_json`. Values are cut to 2,000 characters on the server.                                                                                                                                                                                                                       | Decoding each type in Rust (many types unsupported, precision loss risk).                                                                      |
| Raw bytes for `SQL_ASCII` databases                                                             | The server neither knows nor checks their encoding, so text can be split mid-character or be invalid UTF-8; decoding in Rust with replacement keeps such tables readable.                                                                                                                                                                                                                                                          | Refusing `SQL_ASCII` databases.                                                                                                                |
| Every page read in a `READ ONLY` transaction                                                    | A view or function that writes cannot have side effects from browsing, even on a writable connection.                                                                                                                                                                                                                                                                                                                              | Relying on the session's read-only setting.                                                                                                    |
| Exports streamed by the core to a dialog-chosen file                                            | Complete values and up to a million rows never pass through the webview; memory holds one row at a time. Same native-dialog pattern as connection exports, so the webview never gets a path or file access.                                                                                                                                                                                                                        | Building the file in the webview from loaded pages (cut values, page-sized).                                                                   |
| CSV per RFC 4180, UTF-8 without BOM; NULL empty, empty text `""`                                | The standard most tools read; keeps NULL and empty text distinct. Values are written exactly as stored (no formula escaping), as a database export should be.                                                                                                                                                                                                                                                                      | Excel-specific BOM; prefixing `=`/`+`/`-`/`@` (alters data).                                                                                   |
| JSON export keeps types and exact numbers                                                       | Numbers are written as PostgreSQL prints them (JSON allows any precision); `json`/`jsonb` and arrays are embedded; `NaN`/`Infinity` and anything not valid JSON become strings.                                                                                                                                                                                                                                                    | All values as strings; numbers through `f64` (loses precision).                                                                                |
| Clipboard through `navigator.clipboard`                                                         | Works in the app's webview without a plugin or a new permission; only called from an explicit copy action.                                                                                                                                                                                                                                                                                                                         | `tauri-plugin-clipboard-manager`.                                                                                                              |
| `futures-util` for streaming rows                                                               | The Rust project's standard stream utilities (already a SQLx dependency); rows are read one at a time so a page can stop at its byte budget.                                                                                                                                                                                                                                                                                       | Fetching the whole page into memory first.                                                                                                     |
| `sqlparser` 0.64 for statement classification                                                   | PRD choice; the standard Rust SQL parser (pre-1.0, widely used), with a PostgreSQL dialect and an AST visitor. One input among several: the database-side safeguards hold even if it misreads a statement.                                                                                                                                                                                                                         | Hand-written keyword checks; libpg_query bindings (C library).                                                                                 |
| Split statements with the tokenizer, then parse each                                            | Exact spans for every statement, robust to semicolons in strings, comments and dollar quotes, and one bad statement does not hide the others. Statements the parser does not support (such as `TABLE t`) are refused with its message.                                                                                                                                                                                             | Parsing the whole text at once.                                                                                                                |
| Run reads in a rolled-back `READ ONLY` transaction, extended protocol                           | The server rejects writes even on a write-enabled connection and accepts a single command, so a misread statement cannot smuggle a COMMIT or a second command; the rollback undoes session settings.                                                                                                                                                                                                                               | Simple-query protocol; relying on the session default.                                                                                         |
| Wrap queries as `SELECT <text> FROM (...) AS aidb_q(c1, ...)`                                   | Every value arrives as text (exact and lossless) with the same cut and size limits as table pages; positional aliases keep duplicate or unnamed columns apart. Statements are prepared first, which checks them without running them.                                                                                                                                                                                              | Decoding each type in Rust; the simple-query protocol's text results.                                                                          |
| Statement errors and refusals are outcomes, not app errors                                      | The editor needs the database's own message and the position in the text; these are expected results of running SQL, not faults of the app.                                                                                                                                                                                                                                                                                        | Mapping them to generic app errors.                                                                                                            |
| CodeMirror 6 with a small in-house React wrapper                                                | PRD choice; the official packages (`@codemirror/*`, `lang-sql` with its PostgreSQL dialect). The CodeMirror docs show direct use; a thin wrapper avoids a third-party React binding and lets one editor swap per-tab states.                                                                                                                                                                                                       | `@uiw/react-codemirror`; Monaco.                                                                                                               |
| Editor drafts in a persisted Zustand store (webview local storage)                              | Client-only UI state, which Zustand is reserved for; drafts survive restarts without a schema change. Writes are debounced and flushed on hide; results are never persisted. Clearable from Settings › Storage.                                                                                                                                                                                                                    | Drafts in SQLite through native commands; drafts lost on restart.                                                                              |
| Syntax colors as theme tokens (`--syntax-*`)                                                    | The neutral shadcn palette has no hues to tell keywords, strings and numbers apart; dedicated tokens for light and dark keep the editor on semantic variables and readable (AA contrast) in both themes.                                                                                                                                                                                                                           | Chart tokens (all grey); fixed colors.                                                                                                         |
| Query history recorded by the core, redacted and capped                                         | The webview cannot forge or alter history, and redaction happens before anything is written: shared secret patterns plus role `PASSWORD '...'` literals; 100,000 characters per entry; newest 1,000 kept; removed with the connection (CASCADE); clearable in Settings › Storage.                                                                                                                                                  | History written by the webview; unredacted or unlimited history.                                                                               |
| Result pages by running the statement again with an offset                                      | Same model as table pages: no server-side cursor or transaction is held between pages, so no locks or snapshots linger. Pages can differ if data changes; only first pages enter history.                                                                                                                                                                                                                                          | Server-side cursors held open; caching every page in memory.                                                                                   |
| Saved queries in SQLite, linked to tabs by id                                                   | Kept with the other local metadata and counted in Settings › Storage; a tab opened from a saved query updates it on Save, and asks for a name again if it was deleted.                                                                                                                                                                                                                                                             | Saved queries in webview storage; always saving a copy.                                                                                        |
| SQLx statement logging turned off for PostgreSQL                                                | By default SQLx logs slow statements with their full text; editor SQL and object names must not reach the log.                                                                                                                                                                                                                                                                                                                     | Filtering the `sqlx` target in the log subscriber.                                                                                             |
| reqwest 0.13 with `rustls-no-provider` and `ring` installed as rustls's provider                | PRD choice of HTTP client. reqwest's own documented route for this mode is installing a process-default provider; `ring` is the one SQLx already uses, so the app ships one crypto stack and avoids building aws-lc. reqwest still verifies with the OS trust store (platform verifier).                                                                                                                                           | reqwest's default features (adds aws-lc-rs); `native-tls`.                                                                                     |
| Provider adapters over raw HTTP, not SDKs                                                       | There is no official Anthropic SDK for Rust, and the OpenAI Chat Completions protocol is what Ollama and other local servers implement. Both adapters follow the providers' documented wire formats.                                                                                                                                                                                                                               | Community SDK crates; an OpenAI-compatible shim for Anthropic.                                                                                 |
| A small in-house SSE decoder                                                                    | Follows the WHATWG event-stream rules in about a hundred tested lines and enforces our own event size limit.                                                                                                                                                                                                                                                                                                                       | `eventsource-stream` (no size limit).                                                                                                          |
| `AiProvider` trait with `impl Future` methods and a `ProviderClient` enum                       | Same static-dispatch style as `DatabaseAdapter`; the enum picks the adapter per profile without boxing; tests use fakes.                                                                                                                                                                                                                                                                                                           | `async-trait` with `dyn` providers.                                                                                                            |
| Cancellation by dropping the request                                                            | Closing the connection is how streaming HTTP APIs are cancelled; a cancel signal and a time limit wrap each request (`services::ai::chat`). Verified against llama.cpp, which logs the task cancelled.                                                                                                                                                                                                                             | A provider-specific cancel call (none exists for these APIs).                                                                                  |
| Retries as the official SDKs do: two, with backoff, before a response starts                    | Matches the Anthropic and OpenAI SDK defaults (connection errors, 408/409/429/5xx, `retry-after`, `x-should-retry`). Also covers a pooled connection the server closes just as it is reused, seen with llama.cpp. Nothing is retried once a stream begins.                                                                                                                                                                         | No retries; retrying mid-stream.                                                                                                               |
| No redirects; loopback endpoints bypass proxies                                                 | A redirect could carry the API key to another host; a local model's prompts should never leave the machine through a proxy.                                                                                                                                                                                                                                                                                                        | Following redirects; proxying everything.                                                                                                      |
| Anthropic: buffered tool input, automatic caching, no refusal fallbacks                         | Tool inputs here are short, so the API's default buffering (which validates the JSON server side) costs nothing; automatic caching makes repeated agent turns cheaper; the server-side fallback beta is model-specific, so a refusal is reported as a stop reason instead.                                                                                                                                                         | Eager tool-input streaming; fallbacks enabled for every model.                                                                                 |
| OpenAI-compatible tool calls and structured output as settings                                  | Servers differ (`json_schema`, `json_object`, or neither); 7.2's "Test provider" can detect what an endpoint supports.                                                                                                                                                                                                                                                                                                             | Assuming OpenAI's full feature set everywhere.                                                                                                 |
| Real-endpoint contract tests, ignored by default                                                | Hosted APIs need keys and cost money, and CI has no model server; the same checks run locally against any endpoint. Verified against llama.cpp's server with Qwen2.5 1.5B and against the Anthropic API with `claude-opus-5-5`.                                                                                                                                                                                                    | Mock-only tests; a model server in CI.                                                                                                         |
| Provider kinds as presets over two protocols                                                    | Anthropic uses its own adapter; OpenAI, Ollama and any compatible server share the Chat Completions adapter, with per-kind defaults (endpoint, whether a key is required, the output-limit field: `max_completion_tokens` for OpenAI, `max_tokens` elsewhere).                                                                                                                                                                     | One kind per protocol, leaving defaults to the user.                                                                                           |
| Endpoint trust checked on save and on every use                                                 | PRD: plain HTTP only for loopback unless acknowledged. Re-checking when a client is built means a damaged or hand-edited row cannot send prompts or keys unencrypted. The acknowledgement is cleared when not needed, so it never carries over to a later endpoint.                                                                                                                                                                | Checking on save only.                                                                                                                         |
| "Test provider" probes features with short, fixed prompts                                       | Servers differ in tool calls and JSON modes, and model lists rarely say. Four small requests show what works; the result is saved and drives later requests, and is dropped when the kind, endpoint or model changes. ## Security configuration

| Decision                                                                                           | Why                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Strict CSP: `script-src 'self'`, `object-src 'none'`, `form-action 'none'`, IPC-only `connect-src` | Blocks injected scripts and outbound requests from the webview. All network traffic goes through the Rust core.                                                                                                                         |
| `style-src 'self' 'unsafe-inline'` with `dangerousDisableAssetCspModification: ["style-src"]`      | Radix overlays and Sonner insert `<style>` elements at runtime; Tauri's nonces would otherwise disable `'unsafe-inline'` and break them. Accepted risk: CSS injection without script execution. Scripts keep Tauri's hashes and nonces. |
| No explicit `frame-src`                                                                            | The isolation iframe's origin is generated per build and appended to `default-src` by Tauri; an explicit `frame-src` would block it.                                                                                                    |
| `freezePrototype: true`                                                                            | Official option that blocks prototype pollution from dependencies.                                                                                                                                                                      |
| Minimal capability                                                                                 | Main window gets `core:event:default` plus the app's own commands; nothing else.                                                                                                                                                        |
